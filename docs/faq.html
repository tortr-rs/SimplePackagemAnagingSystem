SPAS

SimplePackagemAnagingSystem — a native package manager for Gentoo
Home | Features | Download | Installing | Manual | FAQ | Source | Bugs

Why?

To have a Gentoo package manager that is a single native binary, with no Python and no Portage underneath, while staying compatible with everything Portage writes.

Is the name spelled correctly?

Yes: SimplePackagemAnagingSystem, abbreviated SPAS.

Can I use it next to emerge?

Yes. Both read /etc/portage and write /var/db/pkg and the world file in the same format, so packages installed by one are seen by the other. Binary packages, the preserved-libs registry and autounmask changes are shared too.

How do I know it does the right thing?

Run hoard install -p ... and emerge -p ... side by side. During development, hoard's @world update plan, depclean list, @preserved-rebuild set, ELF metadata and Manifests were compared with Portage's on a real system and matched.

Is it ready?

It is young (0.x). It builds and installs real packages, but keep Portage installed as a fallback and read the list of what is not implemented.

Which EAPIs?

7, 8 and 9.

Does it verify what it downloads?

Yes. Repository trees are checked against Gentoo's OpenPGP-signed Manifests, distfiles against their BLAKE2B and SHA512 sums, binary packages against their signed Manifests, and git commits against the configured key.

What is the license?

The 2-clause BSD license.

Other distributions? BSD ports?

Not now. SPAS is about Gentoo.

I found a bug.

Report it at https://github.com/tortr-rs/SimplePackagemAnagingSystem/issues, ideally with hoard install -p output and what emerge does instead.
