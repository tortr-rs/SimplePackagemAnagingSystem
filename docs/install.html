1. As a Gentoo package (recommended)

hoard lives in its own small overlay as sys-apps/spas. Installed this way, it is updated like any other package, by hoard itself or by emerge.

# cat > /etc/portage/repos.conf/spas.conf <<'EOF'
[spas]
location = /var/db/repos/spas
sync-type = git
sync-uri = https://github.com/tortr-rs/spas-overlay.git
EOF
# emerge --sync spas            # or, with hoard already around: hoard sync spas
# emerge sys-apps/spas          #                              hoard install sys-apps/spas

From then on, hoard sync && hoard upgrade brings in new versions. The package builds from source with cargo and installs /usr/bin/hoard.

Note: if you installed a binary into /usr/local/bin before, remove it; it comes first in PATH and would hide the packaged one.

2. The prebuilt binary

$ tar xJf hoard-0.3.1-x86_64-linux-gnu.tar.xz
$ sudo install -m755 hoard-0.3.1-x86_64-linux-gnu/hoard /usr/local/bin/hoard

A binary installed this way updates itself:

$ hoard self-update --check     # is there something newer?
$ sudo hoard self-update

self-update checks the download against the release's SHA256SUMS and runs the new binary once before swapping it in. A hoard installed as a package refuses and tells you to use hoard upgrade instead.

3. From source

$ git clone https://github.com/tortr-rs/SimplePackagemAnagingSystem.git
$ cd SimplePackagemAnagingSystem
$ cargo build --release
$ sudo install -m755 target/release/hoard /usr/local/bin/hoard

Needs Rust 1.85 or newer (edition 2024).

Requirements

  • Gentoo (or anything with the Gentoo repository and a selected profile)
  • bash (ebuilds are bash), git and/or rsync for syncing, gpg for signature checks
  • Optional: sys-apps/sandbox, used for builds when installed

Nothing from Portage is needed. Configuration stays where it was: /etc/portage/make.conf and friends.
