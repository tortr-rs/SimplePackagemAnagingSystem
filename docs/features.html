Everything below is implemented natively in hoard. Where Portage has an equivalent, hoard reads and writes the same files.

Shares Portage's files

whatwhere
configuration/etc/portage/make.conf, package.use, package.accept_keywords, package.mask, package.unmask, package.license, package.env + env/, bashrc, patches/, profile/, repos.conf, make.profile
installed packages/var/db/pkg (same layout, environment.bz2, CONTENTS, COUNTER)
world file/var/lib/portage/world
distfilesDISTDIR (default /var/cache/distfiles)
binary packagesGLEP 78 .gpkg.tar in PKGDIR, with a Portage-format Packages index
preserved libraries/var/lib/portage/preserved_libs_registry

Dependency resolution

  • Versions and atoms per PMS: every operator, =*, slots and sub-slots, := and :*, repository constraints, USE dependencies with defaults, blockers.
  • || groups with backtracking (preferring what is installed), REQUIRED_USE, slot conflicts, --update/--deep/--newuse, dynamic dependencies of installed packages, automatic rebuilds after sub-slot changes, weak and strong blockers.
  • Profile stack with parent inheritance, incremental variables, USE_EXPAND, use.force/use.mask (and the stable variants), license groups, keywords.
  • When nothing fits, hoard works out the cheapest configuration change (a USE flag, a ~arch keyword or a license; never a package.mask override), shows it and writes it to zz-hoard-autounmask once you confirm.

Building and merging

  • Its own ebuild environment: inherit, EXPORT_FUNCTIONS, every PMS helper for EAPI 7, 8 and 9, default phases, nonfatal, saved environments between phases.
  • Builds run as the portage user, in a private network namespace, inside sys-apps/sandbox when installed.
  • Parallel builds with -jN: independent packages build at once, merges stay in dependency order.
  • Collision protection, CONFIG_PROTECT with ._cfg files, atomic replacement of every file, pkg_* phases also for packages Portage installed.
  • preserve-libs: a library an upgrade would delete is kept while installed programs still link to it; hoard install @preserved-rebuild rebuilds them. A built-in ELF reader writes NEEDED.ELF.2, PROVIDES and REQUIRES exactly like Portage does.

Binary packages

  • Prebuilt packages straight from the official Gentoo binhost (-g or FEATURES=getbinpkg). A binary is used only when version, slot, IUSE and every USE flag match exactly; otherwise hoard builds the ebuild.
  • Every binary package's Manifest is verified with the Gentoo release key before anything is unpacked.
  • Your own builds can be saved as binary packages (-b or FEATURES=buildpkg) and reinstalled in a second (-k). Portage reads them too.

Repositories

  • rsync trees are checked against their OpenPGP-signed Manifests, every file.
  • git repositories get their newest commit's signature checked (on by default for ::gentoo); a bad one is rolled back.
  • hoard sync clones overlays that were never fetched; auto-sync = no and sync-depth are honoured.
  • Metadata from the repositories' md5-cache, regenerated for stale entries.

Not implemented (yet)

Package sets other than @world, @system, @selected and @preserved-rebuild; signing your own binary packages; --keep-going after a failed build in parallel mode; signature checks for git repositories whose mirrors don't sign commits (such as ::guru).
