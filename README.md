# SimplePackagemAnagingSystem (SPAS)

A native package manager for Gentoo, written in Rust. Its command is `hoard`.

SPAS is an alternative to Portage, not a front end for it. It reads the Gentoo
repositories, resolves dependencies, runs ebuilds in its own EAPI 7/8/9 bash
environment, merges the results and records them, all without Python or any
part of Portage.

It shares Portage's on-disk formats, so the two can manage the same system:

| what | where |
|---|---|
| configuration | `/etc/portage/make.conf`, `package.use`, `package.accept_keywords`, `package.mask`, `package.unmask`, `package.license`, `package.env` + `env/`, `bashrc`, `patches/`, `profile/`, `repos.conf`, the selected `make.profile` |
| installed packages | `/var/db/pkg` (same layout, `environment.bz2`, `CONTENTS`, `COUNTER`) |
| world file | `/var/lib/portage/world` |
| distfiles | `DISTDIR` (default `/var/cache/distfiles`) |

## Usage

```
hoard install <pkg...>     install (-p pretend, -1 oneshot, -u -D -N, -n, -f fetch only,
                           -g use binaries, -S build everything from source)
hoard upgrade              update everything (install -uDN @world)
hoard remove <pkg...>      uninstall
hoard autoremove           uninstall what @world/@system no longer needs
hoard sync                 sync repositories; rsync trees are verified (OpenPGP + Manifests)
hoard search <regex>       search names (-d: descriptions too)
hoard info <pkg>           versions, masks, keywords, USE
hoard list | files | owns  query installed packages
hoard env-update           regenerate /etc/profile.env, csh.env, ld.so.conf
hoard verify [repo]        check a tree against its signed Manifests
```

Package names without a category work (`hoard install tree` asks if it is ambiguous).

## What it implements

- **Versions and atoms** per PMS: all operators, `=*`, slots and sub-slots, `:=` and `:*`,
  repository constraints, USE dependencies with defaults, blockers.
- **Configuration**: profile stack with `parent` inheritance, incremental variables,
  `USE_EXPAND` (user settings replace the profile's), implicit IUSE, `use.force`/`use.mask`
  (including the `stable` variants), `package.*` files, license groups, keywords (`~arch`, `**`, `*`).
- **Metadata**: the repositories' `md5-cache`, validated against ebuild and eclass checksums;
  stale or missing entries are regenerated by sourcing the ebuild (cached in `/var/cache/hoard`).
- **Resolver**: `||` groups with backtracking (preferring installed choices), USE dependencies,
  `REQUIRED_USE`, slot conflicts, `--update`/`--deep`/`--newuse`, dynamic dependencies for
  installed packages, automatic rebuilds after sub-slot changes, weak and strong blockers,
  and build-dependency-first merge ordering.
- **Fetching**: Gentoo mirrors (hashed layout), `mirror://` third-party mirrors, `RESTRICT=mirror/fetch/primaryuri`,
  size + BLAKE2B + SHA512 checks against the Manifest.
- **Binary packages**: prebuilt `.gpkg.tar` packages from the official Gentoo binhost
  (`releases/<arch>/binpackages/23.0/...`, or `PORTAGE_BINHOST`), used when `FEATURES` has
  `getbinpkg` or with `-g`. A binary is chosen only when version, slot/sub-slot, IUSE and every
  USE flag match exactly; otherwise the ebuild is built. Downloads are checked against the index,
  then the package's own Manifest is verified with the Gentoo release key before anything is
  unpacked. Build dependencies of binaries are skipped (unless `--with-bdeps=y`), and sub-slot
  rebuilds only take a binary that was built against the new sub-slot.
- **Ebuild environment** (`src/ebuild.sh`): `inherit`/`EXPORT_FUNCTIONS` with metadata accumulation,
  every PMS helper for EAPI 7, 8 and 9 (`econf`, `emake`, `unpack`, `eapply`, `eapply_user`,
  `do*`/`new*`, `dosym -r`, `einstalldocs`, `ver_*`, `ver_replacing`, `edo`, `pipestatus`, `has_version`, ...),
  default phase functions, `nonfatal`, `die` from subshells, and saved environments between phases.
- **Build isolation**: unpack through test run as the `portage` user (`userpriv`), in a private
  network namespace (`network-sandbox`, loopback up), inside `sys-apps/sandbox` when installed.
- **Install processing**: stripping (`dostrip`, `RESTRICT=strip`), doc compression
  (`docompress`, `PORTAGE_COMPRESS`), `/etc/portage/bashrc` phase hooks.
- **Merging**: collision protection (`protect-owned`, `collision-protect`), `CONFIG_PROTECT` with `._cfg`
  files and `config-protect-if-modified`, atomic replacement of every file, merged-/usr aware unmerging,
  `pkg_preinst/postinst/prerm/postrm` (also for packages Portage installed, from their saved environment),
  env-update and ldconfig.

## Not implemented (yet)

Building your own binary packages (`buildpkg`), `preserve-libs`, parallel builds of several packages, `@sets` other than
`@world`/`@system`/`@selected`, signature checks for git-synced repositories, and automatic
writing of USE/keyword changes (hoard prints the line to add instead).

## Building

```
cargo build --release
sudo install -m755 target/release/hoard /usr/local/bin/hoard
```
